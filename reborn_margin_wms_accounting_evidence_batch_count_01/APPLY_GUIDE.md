# 회계자료·전체 순위·Excel 일괄 분석 적용 안내

버전: `reborn-accounting-evidence-batch-count-01`

## 이번 결과물

- 기존 앱에 회계자료 메뉴를 추가했습니다. 별도 앱이나 샘플 화면이 아닙니다.
- 주문 통계는 기존 최근 30일 기준을 유지하면서 활성 상품 전체 목록을 표시합니다. 30일→7일→오늘→상품명 정렬과 기존 순번을 유지합니다. 기록 없는 상품은 순위 없이 별도 표시하고, 비활성 상품·자재는 제외합니다.
- 독립 Excel 건수 계산기는 여러 파일을 누적 선택합니다. WMS 재고 차감과 별개이며 한 유효 행을 한 건으로 셉니다. H 안의 낱개 수량은 곱하지 않습니다.
- 판매자 펼침 표는 상품 문구를 줄바꿈하고 건수 영역을 짧게 유지합니다. 긴 표는 화면 300항목, 판매자는 50개씩 더 보기이며 검색·다운로드는 전체 포함 결과를 사용합니다.
- 기존 SKU·원가·포장 규격·비활성 목록·WMS 차감·마진·용역비·백업 state는 변경하지 않았습니다.

## 사진 공개 범위

| 역할 | 조회 | 등록·분류 수정·휴지통·복원 | 원본 다운로드 |
|---|---|---|---|
| 로그인 없음 | 일반 목록의 공개 미리보기·날짜·업체·유형·검토·공개 메모 | 불가 | 불가 |
| 기존 허용 관리자 계정 | 위 항목 및 휴지통·변경 이력 | 가능 | 가능 |

앱 주소는 비밀번호가 아닙니다. 공개 미리보기와 분류 정보는 앱 화면 밖의 API에서도 조회할 수 있습니다. 이미 내려받은 파일은 회수할 수 없습니다. 등록할 때마다 공개 확인을 요구하며, 얼굴·계좌·주소·전화번호 등 사진에 찍힌 내용은 자동으로 가려지지 않습니다.

원본은 비공개로 보존합니다. 서버가 JPEG 미리보기와 썸네일을 다시 만들어 EXIF 등 부가정보를 제거합니다. 이 처리는 사진 속 글자나 얼굴의 익명화가 아닙니다. 원본에는 원래 EXIF가 남습니다.

관리는 기존 관리자 계정 기준입니다. 특정 물리 PC에 묶은 인증은 아니므로 같은 관리자 계정으로 로그인한 다른 PC에서도 관리할 수 있습니다.

## 이미 설정한 사진 저장 기반

사용자의 별도 저장소·권한 추가 승인에 따라 기존 연결 프로젝트에 다음을 추가했습니다. 기존 WMS 테이블·RLS는 변경하지 않았습니다.

- 사진 전용 테이블 4개: `reborn_evidence_items`, `reborn_evidence_files`, `reborn_evidence_events`, `reborn_evidence_admins`.
- 비공개 Storage 버킷: `reborn-accounting-evidence`.
- 관리 API: `reborn-evidence-api`. 각 POST에서 Supabase Auth의 사용자 검증과 서버 관리자 목록을 다시 확인합니다. 게이트웨이 JWT 자동 검사 대신 함수 내부 검증을 사용하며 인증 없는 POST는 401로 거부됨을 확인했습니다.
- 기존 앱의 허용 관리자 1명을 사진 관리자 목록에 등록했습니다. 비밀키를 프런트엔드에 추가하지 않았습니다.
- 검사 시 사진·원본 메타데이터·사진 이력은 각각 0건입니다. 운영 사진이나 주문을 시험 등록하지 않았습니다.

현재 연결 프로젝트에서는 `backend/evidence-setup.sql`을 다시 실행하지 마세요. 이 파일은 새 환경의 최초 설치용이며 기존 테이블을 덮어쓰거나 재초기화하는 스크립트가 아닙니다. 다른 프로젝트에 옮길 때는 관리자 등록과 API 배포까지 별도 설정이 필요합니다.

## 사진 사용

1. 회계자료에서 관리자 로그인 후 사진 등록을 선택합니다.
2. 증빙일·업체·유형·공개 메모를 지정하고 공개 범위를 확인합니다. 등록일은 서버가 별도로 기록합니다. 업체는 직접 입력한 명칭이며 Excel 판매자와 연결하지 않습니다.
3. JPEG/정지 PNG를 선택합니다. 장당 10MB·1,200만 화소, 일괄 30장·100MB까지입니다. HEIC·PDF·GIF/APNG 등은 지원하지 않습니다.
4. 같은 이미지의 SHA-256은 중복 후보로만 표시합니다. 중복 후보를 추가하려면 명시적으로 확인해야 하며 자동 병합·삭제하지 않습니다.
5. 등록 실패·중단 시 서버 저장 여부가 미확정일 수 있습니다. 새로고침으로 확인하고 같은 대기 항목으로 재시도하세요. 같은 작업 ID는 재시도에 재사용합니다. 분류를 바꾸어 재등록하려면 기존 항목 상태부터 확인하세요.
6. 분류 수정에는 버전 충돌 검사가 있습니다. 다른 PC에서 먼저 수정한 경우 덮어쓰지 않고 실패 안내와 입력값을 유지합니다. 변경 전후 값·시각·행위자는 사진 전용 이력에 남습니다.
7. 휴지통은 공개 목록에서 숨기며 원본은 보존합니다. 자동 영구 삭제·보관기간 정리·고아 파일 삭제는 수행하지 않습니다.

회전·확대는 현재 상세 화면에만 적용됩니다. 원본이나 미리보기 파일을 덮어쓰지 않습니다. 검토 완료는 자료 검토 상태이며 장부 반영·적격 증빙·세금 신고 완료가 아닙니다.

## Excel 일괄 분석 기준

- 기존 C/H/AA 판매자·옵션 기준과 특수 판매자 통합을 유지합니다. AA는 판매자/판매아이디 계열 헤더, C는 사이트/판매자 계열, H는 주문선택사항 계열 헤더를 확인합니다. 새 양식의 WMS 결제·송장 집계와 섞지 않습니다.
- 기본 첫 시트·1행 헤더이며 각 파일에서 시트와 헤더 행을 변경할 수 있습니다. 양식이 불명확하면 해당 파일은 보류합니다.
- 숨김·필터 행도 기존처럼 포함하며 이를 표시합니다. 병합된 빈 값은 자동 채우지 않습니다. 주요 셀 수식은 실행하지 않고 확인 필요로 보류합니다. 취소/반품/환불 상태가 명시된 행과 명백한 합계/소계 표기는 확인 필요로 분리합니다. 모든 취소 양식을 자동 식별하는 기능은 아닙니다.
- X 배송비는 양의 정수 행 금액의 합계입니다. 상품 확인 필요 행의 정상 X 금액도 기존처럼 포함할 수 있습니다. 상품 건수와 배송비의 범위는 다르며, 실제 결제별 수입이나 송장별 택배비 합계가 아닙니다.
- 동일 바이트 파일은 합산 보류하고 확인 후 추가 포함할 수 있습니다. 사이트+K 주문 식별값이 파일 간 겹치면 후보로 표시할 뿐 주문을 자동 삭제·합치지 않습니다. 해당 식별값은 작업 메모리에서만 사용하며 결과 파일에는 내보내지 않습니다.
- 월은 사용자가 지정하는 작업 라벨입니다. 파일명·수정일·주문일을 자동 추정해 날짜 필터를 적용하지 않습니다. 파일 묶음이 해당 월 전체이고 서로 겹치지 않는지는 별도 확인이 필요합니다.
- 파일당 20MB, 작업당 100파일·200MB·25만 행, 시트당 10만 행·201열·300만 셀 범위입니다. 큰 파일은 나누어 처리하세요. 완료·보류·실패·제외를 구별하며 미분석 파일을 0건으로 처리하지 않습니다.
- 결과는 현재 탭 메모리에만 있습니다. 새로고침하면 작업 목록이 사라집니다. 필요한 XLSX/CSV를 내려받아 보관하세요. 파일 추가는 누적이며 제거·합산 제외·초기화는 원본을 지우지 않습니다.
- XLSX에는 요약·파일 목록·판매자 상세/총계·전체 옵션·확인 필요·열 확인·금액별/사이트별 배송비가 포함됩니다. 사용자 문구의 Excel 수식 실행을 막는 처리를 추가했습니다.
- HTTPS 또는 localhost와 Worker/Web Crypto를 지원하는 최신 브라우저가 필요합니다. `file://`로 HTML만 여는 방식은 보장하지 않습니다.

## 백업과 비용

조건별 내려받기는 공개 이미지와 CSV입니다. 관리자 원본 백업은 선택한 조건의 원본·분류·변경 이력 JSON을 별도 ZIP으로 만듭니다. 한 번에 100자료·200MB까지이며, 필터 범위만 내보낸 것이므로 전체 시스템 백업과 다릅니다. 원본 파일명·EXIF·메타데이터가 포함될 수 있으니 비공개로 보관하세요.

휴지통 복원은 지원하지만 내보내기 ZIP의 자동 재등록/전체 시스템 복구는 제공하지 않습니다. 복구는 원본·메타데이터·관리자 권한·서버 설정을 대조하는 별도 승인 작업입니다. 기존 WMS JSON 백업만으로 사진 객체는 복구되지 않습니다. [공식 백업 범위](https://supabase.com/docs/guides/platform/backups)

요금제·결제·지출 상한·컴퓨팅 설정은 변경하지 않았고 현재 계약 플랜은 확인하지 못했습니다. 사진 원본과 파생 이미지 저장량, 공개 조회의 전송량·함수 사용량은 기존 프로젝트 한도를 함께 사용합니다. 공개 트래픽으로 한도가 소진될 수 있습니다. 사용량과 예산을 정기적으로 확인하세요. [공식 가격/할당량](https://supabase.com/pricing)

## GitHub → Vercel 적용

실제 GitHub 업로드·Vercel 앱 배포는 하지 않았습니다. 운영 중인 정적 앱 버전도 이번 작업에서 조회하지 않았으므로 이 ZIP과 같다고 가정하지 마세요.

1. 배포 전 현재 저장소·배포 버전과 사용자 변경분을 보존합니다. 운영 데이터 백업은 별도 보관하되 복구/import하지 않습니다.
2. 승인된 시점에 기존 저장소의 실제 앱 루트에 이 ZIP의 내용을 함께 반영합니다. `script.js`만 교체하지 마세요. 새 count 모듈·Worker·`xlsx-count-parser.min.js`·로컬 `xlsx.full.min.js`·`workflow-tools.css`·회계자료 모듈·`backend/image-guard.mjs`도 필수입니다.
3. GitHub 업로드는 기존 설정상 Vercel 자동 배포를 유발합니다. 실제 앱 루트·운영 브랜치를 확인한 후 진행하세요. 사진 API/DB의 별도 설치 파일을 Vercel 앱 빌드로 자동 실행하지 마세요.
4. PC·모바일 각각 데이터·관리/업무 메뉴 하단에서 `reborn-accounting-evidence-batch-count-01`을 확인합니다. 필요하면 일반 새로고침을 사용하되 사이트 데이터 전체 삭제는 하지 마세요.
5. 기존 재고·마진·Excel 차감·용역비가 기존 값 그대로인지 먼저 확인하고, 공개 조회/관리자 관리/다운로드를 확인합니다. 실제 업무 증빙 1건을 처음 등록할 때는 공개 가능한 사진만 사용하세요.

코드 롤백은 보존한 직전 앱 파일/커밋 또는 Vercel의 직전 배포로 되돌리는 작업입니다. WMS JSON 복구나 재고 보정이 아닙니다. 앱 코드를 되돌려도 새 사진 DB·Storage와 이미 공개/다운로드된 자료는 없어지지 않습니다. 사진의 공개 중지·서버 권한 변경·데이터 복구/삭제는 별도 승인으로 진행해야 합니다.

## 남은 확인

- 실제 관리자 로그인으로 정상 사진 업로드, 두 번째 PC의 익명 조회, 모바일 카메라 사진 방향·메모리 사용량, 실제 인터넷 오류 후 재시도.
- 실제 여러 PC의 동시 수정, 권한 회수, 업체 표기 통일, 증빙일/보관기간 및 백업 담당자 운영 기준.
- 자동화 Chrome에서는 단순 텍스트 다운로드도 취소됐습니다. 생성된 XLSX/ZIP 내용은 메모리에서 다시 열어 검증했으나 OS 다운로드 완료는 실제 브라우저에서 확인해야 합니다.
- 5가지 뷰포트·기본 키보드·포커스·Escape는 검사했습니다. 실제 브라우저 200% 확대와 iOS/Android 실기기는 미검증입니다.
- 기존 이력은 최대 500개 보존 범위이므로 전체 순위가 실제 기간의 모든 주문을 포함한다고 보장하지 않습니다. 기존 기록의 비정상 orderCount와 다른 시간대 해석을 소급 수정하지 않았습니다.
- 새 일괄 계산기 Worker의 읽기 파서는 공식 SheetJS 0.20.3을 분리 사용합니다. 기존 WMS의 0.18.5는 호환성 보호를 위해 유지했으며 공개 취약점이 남아 있습니다. WMS에서는 신뢰할 수 있는 내부 파일만 사용하고, 별도 승인·회귀 검사 후 파서를 갱신해야 합니다. [Prototype Pollution 공지](https://cdn.sheetjs.com/advisories/CVE-2023-30533), [ReDoS 공지](https://cdn.sheetjs.com/advisories/CVE-2024-22363)
- 기존 Auth의 유출 비밀번호 보호 비활성 경고와 기존 WMS RLS 성능 경고는 이번 범위에서 바꾸지 않았습니다. [비밀번호 보호 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)
